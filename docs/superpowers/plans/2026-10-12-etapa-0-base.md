# Etapa 0 — Base: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pasar de `prisma db push` a `prisma migrate`, fijar el comportamiento actual de los servicios con tests de integración contra Postgres real, y reorganizar el código en `src/modules/<dominio>`, sin cambiar el comportamiento ni la UI.

**Architecture:** Tres bloques en orden: (A) migraciones versionadas con `directUrl`; (B) Vitest con dos proyectos (`unit` sin base, `integration` contra `gestion_socios_test`, que se recrea al inicio de cada corrida y se trunca antes de cada test); (C) mover servicios, esquemas Zod, Server Actions y componentes de cada dominio a `src/modules/*`, con los tests de (B) como red.

**Tech Stack:** Next.js 15 (App Router) · React 19 · TypeScript · Prisma 6.19 · PostgreSQL 16 · Zod 3 · Vitest 3.2 · Node 22.

**Spec:** `docs/superpowers/specs/2026-10-12-etapa-0-base-design.md` (contexto: `docs/superpowers/specs/2026-10-12-roadmap-v2-design.md`).

## Global Constraints

- Sin cambios de comportamiento ni visuales; rutas de la app y de la API REST idénticas.
- Sin dependencias npm nuevas.
- Node 22 (CI y Docker ya lo usan). En local: `nvm use 22` — Vitest 3.2 / Vite 7 **no arrancan en Node 18** (`ERR_REQUIRE_ESM`).
- Los servicios siguen recibiendo `clubId` como primer parámetro y filtrando por él.
- La base de tests de integración debe llamarse `*_test`; los tests nunca tocan otra base.
- El `.env` local apunta siempre a `localhost`. Las URLs de Neon solo se pasan en línea y **solo las usa una persona** (Task 11); un agente nunca ejecuta comandos contra Neon.
- Commits locales, **sin push**. Mensajes en español, tercera persona ("Agrega…", "Mueve…"), terminando con la línea:
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
- Prisma ≥ 6.15 bloquea `migrate reset` cuando detecta que lo ejecuta un agente de IA. Si un paso con `migrate reset` es rechazado por eso, **no** forzar la variable de consentimiento: pedirle a la persona que lo corra ella (en Claude Code: `! <comando>`).

## Review Focus

1. **Base local creada con el viejo `db push`** → `migrate deploy` falla con P3005 ("schema is not empty"); se espera que el README indique cómo recrearla y que Task 1 lo verifique sobre una base así.
2. **`npm test` con Postgres apagado** → se espera un mensaje claro ("¿Está levantado? docker compose up -d db"), no un stack de Prisma ilegible (paso de verificación en Task 2).
3. **`DATABASE_URL` exportado en la shell o en CI apuntando a dev/Neon** → los tests de integración usan igual `.env.test` y el guard rechaza cualquier base que no termine en `_test` (tests en `tests/unit/guard.test.ts` + paso de verificación en Task 2).
4. **Inscripciones simultáneas al último cupo** → nunca un error 500: todo rechazo debe tener mensaje para el usuario (`mensajeDeError` ≠ `null`) (test de concurrencia en Task 6).
5. **Server Actions movidas fuera de `src/app`** → siguen funcionando con `.bind(null, slug, …)` y revalidan las mismas rutas (build en Task 10 + flujo de demo manual en Task 11).

```ts
// Los tests de integración truncan tablas: solo pueden correr contra una base *_test.

/** Lanza si la URL no apunta a una base cuyo nombre termine en "_test". */
export function assertTestDb(url: string | undefined): void {
  let nombre = "";
  try {
    nombre = url ? new URL(url).pathname.replace(/^\//, "") : "";
  } catch {
    nombre = "";
  }
  if (!nombre.endsWith("_test")) {
    throw new Error(
      `Tests de integración: DATABASE_URL debe apuntar a una base *_test (recibido: "${nombre || "ninguna"}"). Revisá .env.test.`,
    );
  }
}
```

`tests/helpers/global-setup.ts`:

```ts
import { execSync } from "node:child_process";
import { PrismaClient } from "@prisma/client";
import { testDbEnv } from "./env";
import { assertTestDb } from "./guard";

/**
 * Una vez por corrida: crea la base de test si no existe, la vacía y aplica todas las
 * migraciones desde cero (así también se valida que migran sobre una base nueva).
 * Usa `migrate deploy` y no `migrate reset`: no es destructivo para Prisma y no requiere confirmación.
 */
export default async function setup() {
  const env = testDbEnv();
  assertTestDb(env.DATABASE_URL);
  const url = new URL(env.DATABASE_URL);
  const nombre = url.pathname.slice(1);

  const adminUrl = new URL(url);
  adminUrl.pathname = "/postgres";
  const admin = new PrismaClient({ datasourceUrl: adminUrl.toString() });
  try {
    const existe = await admin.$queryRaw<unknown[]>`SELECT 1 FROM pg_database WHERE datname = ${nombre}`;
    if (existe.length === 0) await admin.$executeRawUnsafe(`CREATE DATABASE "${nombre}"`);
  } catch (e) {
    throw new Error(
      `No se pudo conectar a Postgres en ${url.host}. ¿Está levantado? (docker compose up -d db)\n${String(e)}`,
    );
  } finally {
    await admin.$disconnect();
  }

  const test = new PrismaClient({ datasourceUrl: env.DATABASE_URL });
  try {
    await test.$executeRawUnsafe("DROP SCHEMA IF EXISTS public CASCADE");
    await test.$executeRawUnsafe("CREATE SCHEMA public");
  } finally {
    await test.$disconnect();
  }

  try {
    execSync("npx prisma migrate deploy", { stdio: "pipe", env: { ...process.env, ...env } });
  } catch (e) {
    const salida = (e as { stderr?: Buffer }).stderr?.toString() ?? String(e);
    throw new Error(`Falló prisma migrate deploy sobre ${nombre}:\n${salida}`);
  }
}
```

```ts
import { db } from "@/lib/db";

/** Vacía todas las tablas de negocio (no la de migraciones). Se llama en beforeEach. */
export async function resetDb(): Promise<void> {
  const tablas = await db.$queryRaw<{ tablename: string }[]>`
    SELECT tablename FROM pg_tables WHERE schemaname = 'public' AND tablename <> '_prisma_migrations'`;
  if (tablas.length === 0) return;
  const lista = tablas.map((t) => `"public"."${t.tablename}"`).join(", ");
  await db.$executeRawUnsafe(`TRUNCATE TABLE ${lista} RESTART IDENTITY CASCADE`);
}
```

```ts
export async function crearActividadAction(slug: string, formData: FormData) {
```
